# Spatial Context / Point & Ask

Spatial Context is a core context primitive, not a student-only agent and not a plugin.

## Where it lives

Students read in the browser and in PDFs, not inside StudyOS, so the primitive is delivered by the
browser extension in `apps/extension` (hotkey `Alt+Shift+A`): a freehand pen / circle / box overlay
on any page, a question box next to the mark, and a bundled pdf.js viewer so downloaded or online PDFs
work the same way. The StudyOS shell's Point & Ask view is the history: every mark, answer, and page
lands there and can be carried into the grounded tutor.

Design decision record: `docs/superpowers/specs/2026-09-15-spatial-context-anywhere-design.md`.

## Representation

```text
SpatialContext
  owner_id            student who made the mark (goal optional)
  goal_id?            grounds the answer in that goal's resources when present
  page_url/page_title where the mark was made (web page or PDF)
  marks[]             polygon (freehand points + bbox) | circle | rectangle | point, role reference/source/target
  resolution_json     resolver output: normalized marks, ranked DOM/PDF anchors, confidence, surface, privacy policy
  answer_json         text, turn history, anchors_used, evidence, model metadata
```

`POST /api/spatial-context/ask` takes marks, viewport size, DOM/PDF anchors (text under the mark with
bounding boxes and, for PDFs, page numbers), page metadata, an optional crop, and the question. The
deterministic resolver ranks anchors by overlap first. Answering is delegated to `app/core/spatial/`
(synced verbatim from the standalone Spatial repo by `scripts/sync_spatial.py`): a provider chain
`SPATIAL_PROVIDERS` (default `ollama,nvidia,openrouter,openai,anthropic`) with vision when a crop is
attached, OCR (`rapidocr`) as the fallback for text-in-images, and a deterministic echo when no provider
is reachable. `POST /api/spatial-context/ask/stream` is the same contract as SSE
(`status` -> `delta`* -> `complete` | `error`), which the extension uses to render tokens as they arrive.

## Research mode

`research: true` on `ask`/`ask/stream` (extension toggle **🔎 Verify with sources**, default on) runs
`app/core/spatial/research.py` (synced from Spatial): DuckDuckGo search on question + marked text, fetch
the top pages, keep the passages that overlap the question, and answer under `RESEARCH_SYSTEM` — at most
three sentences, every claim cited `[n]`, "Not settled by sources:" when nothing supports an answer. The
response carries `sources[]` and `cited[]`; `answer_json.sources` persists them. Optional Gemini grounding
when `GOOGLE_API_KEY` is set (pattern from `D:/PROJECTS/Cited Multi-Agent Researcher`).

## Zero-install B2C

- `X-Device-ID` (random UUID generated by the extension on install) maps to an anonymous `User`
  (`role=anonymous`, email `device-<id>@anon.point-ask`) so history and quota exist before sign-up.
  Login/register with the same header adopts that history into the real account (`adopted_marks`).
- Quotas: `SPATIAL_ANONYMOUS_DAILY_LIMIT` (20), `SPATIAL_USER_DAILY_LIMIT` (200) and
  `SPATIAL_DAILY_COST_CAP_USD` (0.10) per owner per day in `spatial_usage`; exceeded -> 429/402 with a
  structured `{code, message}` detail. `GET /api/health` reports providers, speech engines and this
  device's quota. `protocol_version` < server -> 426 `CLIENT_OUTDATED`.
- `POST /api/spatial-context/{id}/quiz` ("Quiz me later") creates a `ReviewItem` with a prompt built
  from the marked text under the user's `Point & Ask` goal; it shows in `/api/review` and Today.
- Speech: the extension uses browser Web Speech + `speechSynthesis` by default. **Power mode** routes to
  `/api/audio/transcribe` (faster-whisper) and `/api/audio/synthesize` (pocket-tts), served in-process or
  proxied to the optional `audio-worker` container (`docker compose --profile audio up`, `SPATIAL_AUDIO_URL`).
- Operators: `spatial_review` in the snapshot lists pending low-confidence marks; `PATCH
  /api/operator/spatial/{id}/review {action: confirm|dismiss}`; analytics carry `spatial_cost`
  (asks today, $ today, $ by provider, review-status counts).

## Deploy to AWS (App Runner + Bedrock)

`.\scripts\deploy_aws.ps1 -Region us-east-1 [-DatabaseUrl postgresql+psycopg://…]` builds `docker/Dockerfile.api`,
pushes to ECR, creates/updates an App Runner service with an instance role allowed to call Bedrock, health check
`/api/health` (reports `db`), and prints the URL. `docker/entrypoint.sh` runs `alembic upgrade head` then uvicorn.
Provider chain on prod: `SPATIAL_PROVIDERS=bedrock`, `BEDROCK_ENABLED=1`, `BEDROCK_MODEL=amazon.nova-lite-v1:0`
(Converse API streaming, vision via image block). Then `package_extension.py --api-base <url>` bakes the URL
into the zip's `config.js`. Guardrails: 10 asks/min burst per actor + daily quotas + cost cap; anonymous
device users and their marks are purged after `SPATIAL_ANONYMOUS_RETENTION_DAYS` (30) by a daily task.

Ask options: `level: eli5|student|expert` (panel segmented control) changes the system prompt;
**diagram mode** triggers automatically when the mark has no readable text but a crop is attached
(vision first, OCR fallback, footer says so).

## Ship checklist

`py -3.12 scripts/package_extension.py` -> `dist/*.zip`; listing and permissions text in
`docs/store/STORE_LISTING.md`; privacy policy served at `/point-and-ask/privacy.html`; landing page at

this one stay one codebase (only `config.js`/`manifest.json` differ).

## Invariants

- A mark establishes reference, never authority. `ask` only explains; any future action still goes
  through permission, risk, approval, execution, and verification.
- Privacy is chosen in the extension: `crop_only` (default), `anchors_only` (no pixels), `full_frame`.
  Operator telemetry never includes marked text or pixels.
- Low-confidence resolutions (< 0.6) flag `confirmation_required` so the UI can ask the student to
  circle tighter before the tutor leans on the mark.
